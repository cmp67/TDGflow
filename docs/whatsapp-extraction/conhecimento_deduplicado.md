## Método

Fonte: seção "Conhecimento de viagem" (linhas ~3170–3807) do arquivo `TDG_Flow_Extracao_WhatsApp_2020-2026.md`, organizada em 3 tipos: `fact` (316), `note` (289), `link` (22) — 627 registros no total.

Diferente das categorias anteriores (hotéis, contatos, reviews), aqui não há um nome de entidade único a normalizar — cada registro é um fato/nota/link independente, com título curto + descrição + fonte (autor, data). A pergunta de deduplicação aqui não é "é o mesmo hotel/contato?" mas sim "é o mesmo fato relatado duas vezes?".

Passos aplicados:
1. **Normalização de título** (NFKD, minúsculas, sem pontuação) — busca de títulos idênticos entre os 627 registros.
2. **Fuzzy matching de título** (`token_sort_ratio >= 80`) — 31 pares candidatos gerados, todos julgados manualmente um a um.
3. **Fuzzy matching de descrição** (`token_sort_ratio >= 75`) — checagem cruzada independente do título, para pegar o caso de conteúdo repetido com título diferente. Só 1 par passou do limiar, e era o mesmo par já achado pelo título.

Cada candidato foi julgado individualmente. A maioria dos pares com título parecido são **falsos positivos do fuzzy match** — o padrão "Restaurantes em/recomendados em [Cidade]" ou "[Destino] - perfil do destino" gera alta similaridade de título entre cidades totalmente diferentes (Veneza x Verona x Roma, Marbella x Menorca, etc.), mas o conteúdo é completamente distinto. Esses foram descartados sem mesclar.

Alguns pares têm título **idêntico ou quase idêntico** mas descrevem fatos genuinamente diferentes (preços cobrados por consultoras diferentes, explicações complementares sobre o mesmo tema por fontes diferentes) — mantidos separados, listados abaixo para transparência, mas **não excluídos da contagem** porque não há ambiguidade real: são fatos distintos, só compartilham tema/título.

Só 1 par era de fato o mesmo conteúdo restatado (mesma autora, atualizando sua própria dica meses depois) — esse foi mesclado, mantendo a versão mais completa/recente.
